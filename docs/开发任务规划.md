## 1. 项目概述

### 1.1 目标

把桌游 **Hit Z Road（亡命之途，设计 Martin Wallace，2016，SPACE Cowboys/Asmodee）** 改编为纯文字电子游戏。规则流程框架沿用实体说明书，**卡牌、骰面、场景文本与特殊道具以个人维护的 Markdown 源表（参考资料/卡牌.md、骰子.md）为唯一内容事实来源**。

### 1.2 三个阶段与明确边界

| 阶段         | 目标平台                                        | 模式        | 形态                                      |
| ---------- | ------------------------------------------- | --------- | --------------------------------------- |
| 阶段 1（当前重点） | Mac 笔记本（CPython 终端）                         | 单人 SOLO   | Rich 纯文字界面，含存档/读档、局后统计与评级               |
| 阶段 2       | M5Stack Cardputer ADV（ESP32-S3，MicroPython） | 单人 SOLO   | 复用同一套规则核心，只新写设备前端                       |
| 阶段 3       | 同 Mac / 同设备                                 | **仅两人热座** | 移除竞拍，D6 比大小定先手（平重掷）+ 每轮轮换；不做 3–4 人、不做联网 |

**明确不做**：任何图片/图形渲染、网络联机、3–4 人模式、promo/扩展内容。

## 2. 规则依据与数字化口径

### 2.1 材料清单（已收齐）

1. 实体说明书照片 11 张：配件、设置、牌堆构成、规划/竞拍/遭遇三阶段、远程与近战、屍群红骰、淘汰、终局计分、1–3 人变体、单人规则、封底评级表；
2. **内容源表（人工维护）**：`参考资料/卡牌.md`（60 张）、`参考资料/骰子.md`（普通/强化骰各 6 面，6 处笔误已全部订正）；历史文件 `亡命之途卡牌及骰子内容.xls` 仅作存档；
3. 盒面照片 2 张。

### 2.2 术语映射（界面一律用右侧简体命名）

| 实体说明书（繁中）          | 数字版（简中/代码键）                          |
| ------------------ | ------------------------------------ |
| 彈藥 / 汽油 / 腎上腺素     | 弹药 ammo / 汽油 gas / **药剂 meds（X 药剂）** |
| 黑色骰子 / 紅色屍群骰       | 普通骰 normal / 强化骰 enhanced            |
| 傷亡（黑骰 6 面）         | 咬伤                                   |
| 可怕地死去（红骰 6 面）      | 死亡                                   |
| 紅色丧尸手 + 小骷髅 1/2/3  | 丧尸等级 level（屍群力量）                     |
| 9 种特殊标记（执行者号、燃烧弹等） | **不使用**，改为用户自设 6 种特殊道具（见 2.5）        |

### 2.3 核心规则口径（实现以此为准）

**Setup（每局）**

- 初始：主幸存者 1 + 跟随者 4（共 5 人）；弹药/汽油/药剂各 4；
- 牌池 60 张（I 16、II 22、III 22，即已剔除左下角 AKQJ 标识卡），**永久锁定 60 张，不再补牌**；
- **每阶段独立洗牌、各随机剔除 4 张**，登场 12 / 18 / 18，按 I→II→III 叠放，跨阶段不混洗；
- 单人每轮发 6 张组 3 条路径（每路径 2 张），选定 1 条后其余 4 张弃置，**每轮固定消耗 6 张**；
- 因此三阶段分别进行 **2 / 3 / 3 轮，共 8 轮**，牌库恰好耗尽。

**单人三路径（说明书第 11 页；v0.6.4 起按难度区分选前奖惩）**

明暗布局两档难度一致；奖惩数值在 `config.json → solo_paths.difficulties` 配置，不写死在代码里：

| 路径  | 两张卡明暗 | 简单（easy，原规则）            | 困难（hard）              |
| --- | ----- | ----------------------- | --------------------- |
| 路径一 | 全暗    | 选前**奖励**：拿 2 个任意资源     | 无奖惩                   |
| 路径二 | 左明右暗  | 正常结算                    | 选前**代价**：付 1 个任意资源     |
| 路径三 | 全明    | 选前**代价**：付 2 个任意资源，不足不可选 | 选前**代价**：付 2 个任意资源，不足不可选 |

- 难度在新游戏时选择（e/h），整局固定，存于 `GameState.difficulty`（旧存档缺省按 easy 兼容）；每轮摆路径时由 `Engine._solo_paths_view()` 按难度取配置，奖惩随后固化进 PathOption；
- 困难难度下路径二也走"任意资源分配"交互，资源为 0 时路径二、三都置灰不可选。

**每张卡三步结算（从左到右）**：① 拾荒（拿左上全部资源）→ ② 事件（黑字立即生效；红字为影响本场战斗的特殊规则）→ ③ 战斗。

**战斗**

1. **远程攻击**（可选、每场仅一次、**且仅能在第一批近战骰之前**）：每付 1 弹药掷 2 颗普通骰，仅"击杀/额外击杀"面杀 1 丧尸，其他面忽略；
2. **逃跑**（**仅近战开始前**）：付 2 汽油，弃掉本牌且不得分；**一旦掷出第一批近战骰，本场后续批次只能继续近战，远程与逃跑永久关闭**；
3. **近战**：每名幸存者掷 1 颗骰；屍群（level 1/2/3）把等量普通骰替换为强化骰，总骰数 ≤ 幸存者人数；一批没清完就再掷一批，循环至一方全灭：
   - 空白：无事；伺机而动：可付 1 药剂杀 1 丧尸，否则视为躲避；
   - 击杀：杀 1；额外击杀：杀 1，且可付 1 药剂再杀 1；
   - 咬伤：付 1 药剂救人，否则损失 1 名幸存者；
   - 死亡（仅强化骰）：立即损失 1 名幸存者；
4. 杀光丧尸 → 赢得卡牌（得分计入终局）；幸存者全灭 → 对局失败。

**终局（单人）**：赢得卡牌的得分总和 + 每凑齐一套（1 幸存者 + 1 汽油 + 1 弹药 + 1 药剂）+1 分；评级表：

| 分数  | 0–5   | 6–10 | 11–15 | 16–18 | 19–21 | 22+    |
| --- | ----- | ---- | ----- | ----- | ----- | ------ |
| 评级  | 神父加百列 | 还好   | 不错    | 非常好   | 叫我达瑞  | 幸运儿或天才 |

| --- | --------- | ---------------------------------------------- |

### 3.3 数据层设计

- 卡牌结构：`{id, stage, order_in_stage, scene, scavenge{ammo,gas,meds}, event_text, event_raw, zombies{count,level}, score}`；其中 `event_text` 为玩家面（选路查看/遭遇展示），`event_raw` 为开发面（effects.py 解析依据），二者均由 md 源表两列分别生成（v0.6.1 起）；
- 骰面结构：`{normal:[{face,name,desc}×6], enhanced:[×6]}`；
- 规则常量集中在 `config.json`（setup、单人路径【v0.6.4 起按 easy/hard 两档难度配置奖惩】、战斗花费、计分、评级、存档、双人模式）；
- 改内容只改 `参考资料/*.md` 或 config，跑 `python3 tools/md_to_json.py` 重新生成，代码不写死。

### 3.4 MicroPython 可移植子集规范（core 层强制）

1. **允许**：基础语法、dict/list/tuple/set、普通类与函数、`json`、`random`（仅经 rng.py）、f-string；
2. **禁止**：`dataclasses`、`enum`、`pathlib`、`typing`（运行期）、`inspect`、装饰器魔法、第三方库；不做 print/input/文件/网络 I/O；
3. 类型注解只写在注释或文档字符串中，避免设备端解释器兼容问题；
4. 每次 core 新增模块，用静态扫描确认无禁用导入（当前已纳入交付前自检）。

### 3.5 随机数与可复现

- 一切随机走 `core/rng.py` 的 `SeededRng`，支持开局传 `--seed`；同种子 + 同操作序列必得到同一局，用于回归测试与复现 bug；
- `SeededRng.get_state/set_state` 可导出/恢复完整随机状态，存档读回后摸牌掷骰序列无缝衔接（已被 M2 测试固化）；
- 阶段 2 设备端如需真随机，只替换 RNG 实现，不动规则代码。

### 3.6 交互与最小屏约束

- 全部操作用**热键选单**（数字键选项、y/n 确认、回车推进），不依赖鼠标；
- 信息架构按 Cardputer **30 列 × 16 行**（240×135 / 8px 估算）设计；Mac 端用 Rich 做配色、面板等增强，但去掉样式后纯文本仍完整可玩。

### 3.7 存档设计（已定案，M5 已落地）

- 整局 `GameState` 提供 `to_dict/from_dict`，引擎 `snapshot/restore` 连随机状态一起保存，JSON 序列化即存档；
- Mac（`save_store.py`）：**每轮末自动存档 1 个（auto.json）+ 3 个手动槽（manual_1..3.json）**，默认存仓库根 `saves/`（已忽略入库），可用环境变量 `ZROAD_SAVE_DIR` 改目录；存档外壳含格式版本与保存时间，菜单可读档续局；阶段 2 落 Flash/microSD；
- 存档记录种子、随机状态、牌库剩余序列、玩家状态、当前轮次/阶段、战斗中途状态、统计累计，支持中途退出续局。

### 3.8 测试策略

- **数据测试**（已建 10 项）：结构、数量、统计锚点、配置自洽、md↔JSON 同步；
- **规则测试**：headless + 固定种子。M2 已覆盖 setup 剔除、三路径明暗与奖惩、每轮消耗 6 张、2/3/3 轮次、存档恢复一致性；M3/M4 继续对每个事件、道具、骰面写用例；
- **整局冒烟**：headless `scripted.py` 可自动打完一整局（多种子），M5 已断言整局闭环、总分恒等式与评级必有结果；App 层另用自动应答替身做整局界面冒烟，覆盖选路/战斗/轮末存档/终局渲染。

### 3.9 引擎状态机（M2 建骨架，M3 接入卡牌结算）

```
new_solo() → PLANNING（摆出3路径）
  choose_path(i, 资源分配) → ENCOUNTER（中选2张入遭遇队列，其余4张弃置）
    对每张卡（current_encounter_card）：
      peek_card_decision() 查看立即效果是否需要玩家抉择
      begin_card_resolution(decision)：
        ① 拾荒入账 → ② 立即事件结算（effects.resolve_immediate）
        → ③a 无丧尸：直接赢得本卡，推进队列
        → ③b 有丧尸：挂起 pending_combat（含本场战斗修正），队列不推进
              Combat 状态机：近战前可选【远程（1弹药2普通骰，仅击杀面，每场一次）】
                            或【逃跑（2汽油弃牌）】或直接近战；
              近战一批：每人1骰、屍群按 level 换等量强化骰（校车+车辆铠甲两件套齐则全普通），
              掷出后返回药剂机会列表，玩家决策后统一结算，循环至一方全灭
              combat_resolve_melee/combat_ranged/combat_flee 收口（M4 已实现）
    两张卡处理完 → ROUND_END → close_round() → 下一轮 PLANNING
  第8轮 close_round → FINISHED（M5 已接 scoring 计分评级）
  任意时刻幸存者归零 → FINISHED（失败）
```

**M3 事件效果分类（effects.py 已实现，60 张卡逐张解析、未识别即报错）**：

| 类别       | 效果                      | 涉及卡                                            |
| -------- | ----------------------- | ---------------------------------------------- |
